# 从恶毒语音资源到独立战斗语音包

本次语音包采用《碧蓝航线》恶毒的录音短片段，替换《影之刃零》中文语音配置下的自机常用战斗发声。语音以独立包安装，剧情和对话范围保留原游戏语音。

## 1. 基础角色编号与实际语音目录

角色 gid 为 `90111`，固定资源快照中对应四组语音 ID。

| 目录 ID | 快照列出的音频数 |
| --- | --- |
| `901110` | 40，包含 12 条 `_ex` |
| `901111` | 8 |
| `901112` | 13 |
| `901113` | 12 |

共 73 条，均完成下载和全段解码。原始格式为 Ogg Vorbis、44.1 kHz、单声道，总时长约 723.70 秒。本次完整度指固定快照列出的资源，后续皮肤、服务器差异和补录需要另查。

下载使用 Fernando2603/AzurLane 提交 `21366bf104dccc515d084b33d61d98ff994dc7f2`，地址从索引取得后将 `main` 替换为该提交。仓库的 `metadata/voice-index.json` 保留所需地址，下载器记录来源、散列、时长和解码状态。[资源仓库](https://github.com/Fernando2603/AzurLane)、[结构说明](https://github.com/Fernando2603/AzurLane/blob/main/docs/VOICELINE.md)

```powershell
python tools/investigate_lemalin_voice.py
python tools/build_lemalin_voice_audition.py
```

生成的试听页为 `output/voice-audition/v1/试听.html`。可分别听短片段、原录音上下文和分组连播，并导出选择备注。

## 2. 从长句挑短音，需要同时考虑语义和触发频率

第一批分为 A 攻击、B 受击/闪避、C 呼吸/待命三组。用户认为 B/C 基本适合，A 组需要核对原文。

| 候选 | 来源与选取思路 | 最终处理 |
| --- | --- | --- |
| A1 | skill 的短句，原文含义为“消失吧” | 保留 |
| A2 | battle 末句，按台词与切点对应“我上了/出击” | 保留 |
| A3 | battle_ex 后半句，孤立后接近“在我这里/寄于我” | 撤出攻击池 |
| A4 | lose 末句，按台词与切点对应“还没完” | 保留 |
| B1–B5 | 低血量、触摸等台词中的惊呼 | 保留 |
| C1–C3 | 详情与好感录音中的哈欠、睡息 | 保留作回气等候选 |

日文语义核对参考了 AzurLaneTools/AzurLaneLuaScripts 中的日文台词。原文、固定切点和人工听辨分别记录，本次未完成所有短音的逐字音频转写。[台词资料](https://github.com/AzurLaneTools/AzurLaneLuaScripts)

攻击短音会频繁触发，残缺长句比受击惊呼更容易产生违和。选材时先听原录音上下文，再连续播放多个攻击片段。允许部分发声事件静音，保留游戏原来的节奏。

初剪输出为 48 kHz、单声道 PCM16，使用短淡入淡出并记录原始切点。重采样服务于接入格式，原素材频率与内容另行保留。[剪辑与语义备注](../tools/build_lemalin_voice_audition.py)、[试听页模板](../tools/lemalin_voice_audition.html)

## 3. Wwise 事件、银行与媒体需要一起维护

游戏使用 AkAudioEvent 与内嵌 Wwise 银行/媒体。当前方案复用前作 2B 已验证的 PCM 内嵌事件布局。

同一事件中至少涉及以下关联数据。

- 事件本身的语言映射、银行和媒体列表。
- 媒体 ID 与银行 SoundSfxVoice 节点的 SourceId。
- 媒体 Hash、CacheId 和 InMemoryMediaSize。
- 银行校验数据及对应打包散列。
- RIFF fmt、采样率、字节率和实际 PCM 时长。
- bulk 资源表的偏移、大小与事件时长字段。

实现会读取参考模板和解析元数据，按真实资源表重建 payload。中文分支使用恶毒短音或静音，参考模板中的其他内嵌语言分支保留原字节。

静音媒体按原时长换算成 48 kHz PCM，保留原随机容器和事件路由。输出为 `.uasset/.uexp/.ubulk` 后，经 retoc 转为 UE5.7 IoStore 三件套。

这套写入方式针对已核对模板，代码中的唯一出现次数、格式和长度断言用于阻止误写其他布局。不同银行版本、编码器或资源表结构需要重新解析。[事件替换实现](../tools/build_lemalin_voice.py)

## 4. 语音模板是重要的外部输入

设置 `LEMALIN_REFERENCE_ROOT` 指向自己的参考工作目录，当前脚本使用这些相对路径。

```text
参考工作目录/
  work/audio-research/reference-battle03-legacy/
    scriptobjects.bin
    ProjectPBZ/Content/Wwise/Events/VO/Int/Hun/Battle/
      SFX...uasset
      SFX...uexp
      SFX...ubulk
  work/audio-research/reference-battle03/
    SFX...json
  tools/retoc/package/retoc.exe
```

这里的模板为前作已经核对并适配为 PCM 内嵌布局的参考事件。原游戏直接导出的任意银行未必符合本脚本的写入前提。制作侧还需要建立对应解析元数据，复用时先核对语言、PluginId、SourceId 和 bulk 表。

脚本使用的 `scriptobjects.bin`、事件模板及银行数据由制作侧准备，仓库提供替换实现与结构约定。`RETOC` 环境变量可单独指定可执行文件。

```powershell
$env:LEMALIN_REFERENCE_ROOT = '你的参考工作目录'
$env:RETOC = '你的工具目录/retoc.exe'
python tools/build_lemalin_voice.py
```

## 5. 从首批替换到战斗覆盖补全

首批复用 17 个事件、130 个媒体槽。后续用户仍然频繁听到原男声，沿原游戏战斗事件范围补齐到已知 42 个事件。

- 39 个发声事件的中文分支完成替换或静音，共 289 个中文媒体槽。
- `HuXi_Fast`、`HuXi_Slow` 为无动作空事件。
- `JinGu_Long_Stop` 为无媒体的停止事件，保留控制逻辑。

范围位于 `VO/Int/Hun/Battle`。普通攻击从 `ChuZhao_02` 入手的定位经验来自 2B 项目的事件引用调查，事件名字只作为候选线索。

受击事件使用 B 池，出招、蓄力和释放等按用途分配 A 池，部分收招与吸气使用 C 池。咳嗽、打嗝、部分长发声使用静音。攻击和回气大致按三分之一媒体槽设置有声，具体数量由事件媒体数计算，受击事件使用更密的有声分配。

覆盖表要区分发声、空事件和停止事件，还应确认实际语言分支。单纯遍历文件名很容易遗漏常用声，也可能误改剧情或控制事件。

## 6. 响度用少量抽样和实机确认收敛

第一版用户反馈偏小。本次最后只抽取 5 条原版短音，按 20 ms 帧剔除静音，活跃段 RMS 平均约为 -14.66 dBFS。它用于粗略参照，未做逐事件一一匹配。

最终所有有声片段统一增加 3 dB，以 .95 限峰，取消早期 C 池额外的 .6 音量衰减。音频时长和触发分配保持对应构建中的约定，用户实机确认可接受。

剪辑池、RMS、峰值与触发密度一起影响听感。新角色的声音不同，+3 dB 仅作为这次的结果记录。先小量抽样、进游戏听，再根据明确反馈调整，能够避免把响度比较扩成全库研究。[原版抽样工具](../tools/VoiceLoudnessProbe/Program.cs)

## 7. 为什么最终采用独立包

当前模型面板使用普通 UE 蓝图设置，语音通过同路径 AkAudioEvent 资产覆盖。调查到的事件没有现成可用的 Switch/State 路由供面板切换两套语音。

真正实时切换原声与恶毒声，需要同时保留两套声音并增加事件分支或运行时路由。当前选择低成本且已经实机确认的方式，将语音包独立安装，关闭游戏后安装或移除，下次启动生效。

当前发布范围要求中文语音设置。剧情、对话继续使用原游戏语音，其他语言配置的替换范围未作验证。
