# 从 MMD 模型到游戏制作工程

这份流程按 LeMalin 实际使用的制作链整理。外观基线为 `0.2.0-dev.30`，语音基线为 `0.1.0-dev.3`。角色和语音分开构建。

## 环境与目录

本次使用 Windows、Blender 5.2.3、MMD Tools 4.5.14、UE 5.7。编辑器模块需要对应 UE 的 C++ 构建环境。普通 Python 依赖见根目录 `requirements.txt`，资源调查探针使用 .NET 10 和 csproj 中声明的 CUE4Parse 包版本。

```powershell
python -m pip install -r requirements.txt
$env:UNREAL_ROOT = 'D:/Epic Games/UE_5.7'
$blender = 'D:/Projects/MMD/blender-5.2.3-windows-x64/blender.exe'
New-Item -ItemType Directory -Force source/tex, work, work/textures, work/motion, output/reports, output/preview, output/motion, output/lively | Out-Null
```

上面的工具路径是示例，按自己的安装位置修改。`source` 存输入，`work` 存中间文件，`output` 存预览、报告和成品。UE 制作项目位于 `project/ProjectPBZ`。

## 首次接入需要准备的资产

| 输入或工程资产 | 本次用途 |
| --- | --- |
| `source/LeMaline v1.0.pmx` 与完整 `source/tex` | 当前模型专用脚本的输入 |
| `/Game/Hcx2B/SK_SourceHun` | 原游戏主角的参考骨架与重定向源网格，目录名来自前作 |
| `/HuaShira/Characters/Hero/Hero_Hun` 下的身体、挂件及对应骨架/物理引用 | 建立显示覆盖和运行时所需引用 |
| `/Game/PBZContent/Characters/Hero/Hun_New_V2b/Material/MI_ZeroHun_Cloth_03_b` 及其依赖 | 编辑器中创建材质实例，运行时使用游戏已编译着色器 |
| `work/native-ui/assets` 内本地导出的字体、箭头、纸纹等 | 创建同路径的编辑器 UI 预览资源 |
| `/Game/LeMalin/DiagnosticsRuntime/A_Hun_TangBlade_Walk_Fwd_Loop_Soul` | 动态生成器离线运行入口使用的参考动作 |
| `work/motion/*-samples.json` | 可选的原版动作采样，用于动作预览与诊断 |
| `work/eye-gem/generated-atlas.png` | 宝石眼美术输入，按当前原图 UV 和 alpha 重新封装 |

源角色、同路径参考包和游戏材质桩沿用了前作的本地制作项目。当前仓库提供生成侧代码和资源路径约定，首次从空项目建立这些游戏参考资产仍需自行导出、导入或建立对应桩。制作侧脚本依赖的引用必须完整，尤其要保留原骨架引用、源角色动画所需信息和游戏材质参数结构。

项目的 `HuaShira` 内容插件描述用于创建对应挂载点。制作侧 `PBZContent` 资源用于让编辑器认识相同路径，最终玩家包由白名单排除这些参考资源，运行时解析游戏本身的同名资源。

## 第一步，导入、记录和变形骨架

```powershell
& $blender --background --python tools/import_preview.py
& $blender --background --python tools/prepare_game_model.py
& $blender --background --python tools/prepare_lively_model.py
python tools/investigate_hair.py
```

`import_preview.py` 保留原始 MMD 材质工程，另建 PBR 材质预览，输出正面、侧面和背面图。它为默认安装的 MMD Tools 加入扩展目录、解压 wheel 依赖，并尝试补全公共 Toon 路径。

`prepare_game_model.py` 以真实源 Armature 骨名筛选权重，建立人体映射与权重别名，再保留有实际权重的辅助链。输出为厘米制的游戏制作骨架。MMD 的 D 骨、扭转骨和附加链处理来自当前模型，换模型时先核对映射与辅助骨命名。

`prepare_lively_model.py` 导出 Blink、三套眼皮/脸部预设和四方向眼神，共 11 个形态键。眼神烘焙读取原 PMX 的眼骨和目戻补偿，依赖顶点顺序保持一致。

这一步至少确认权重真实有效、贴图引用齐全、形态键可用。完整的原模型和每个阶段中间文件分别保留，方便回到出问题的环节。

## 第二步，编辑器模块和基础重定向

```powershell
./tools/build_editor.ps1
$env:LEMALIN_FULL_IMPORT = '1'
./tools/run_unreal.ps1 ue_build_prototype.py
./tools/run_unreal.ps1 ue_prepare_game.py
```

全模导入后，`ue_build_prototype.py` 建立源/目标 IK Rig 与 `RTG_Hun_LeMalin`，按链映射并对目标参考姿态做自动对齐。当前主要采用 FK 链与 pelvis 运动，手臂比例及握点保留本次接受的效果。

`ue_prepare_game.py` 建立基础材质实例及基础动画蓝图，并以目标网格替换 `Hun_Hair_Band` 显示入口。最终动态阶段会再次覆盖这一显示资产。

这个脚本会重建基础白名单和材质绑定。后续增量制作时，先明确它是否会覆盖自己已经完成的动态或材质设置，再决定执行范围。

## 第三步，材质与外观变体

按依赖顺序准备贴图，然后导入对应材质实例。

```powershell
python tools/prepare_surface_detail.py
python tools/prepare_sun_comparison.py
python tools/prepare_black_style.py
python tools/prepare_sheer_stockings.py
python tools/prepare_eye_finish.py
./tools/prepare_eye_gem.ps1 -GeneratedAtlas ./work/eye-gem/generated-atlas.png

$env:LEMALIN_PLAYER_RELEASE = '1'
$env:LEMALIN_SKIP_VERIFICATION = '1'
$env:LEMALIN_MATERIALS_ONLY = '1'
./tools/run_unreal.ps1 ue_apply_surface_detail.py
./tools/run_unreal.ps1 ue_prepare_sun_comparison.py
./tools/run_unreal.ps1 ue_build_black_style.py
./tools/run_unreal.ps1 ue_build_sheer_stockings.py
./tools/run_unreal.ps1 ue_build_eye_finish.py
Remove-Item Env:LEMALIN_MATERIALS_ONLY
```

眼睛的美术输入需要自行准备。`LEMALIN_MATERIALS_ONLY=1` 用于先生成材质，待所有依赖就绪后统一生成动态与面板。丝袜脚本保留了诊断图和材质的生成；玩家分支跳过依赖旧版配色图片的 Previous 对照，并由玩家面板只暴露最终黑色选项。

黑色风格的原样/Half/Quarter 等后缀沿用开发期命名，具体倍率已调整，不能只按后缀猜颜色值。玩家黑色选项最终使用 dev.23 的哑光薄袜配色。

## 第四步，物理、表情、眼神和玩家面板

先用 `NativeUiProbe` 从自己的本地游戏资源导出预览所需文件。探针要求 `PBZ_PAKS` 和 `LEMALIN_REFERENCE_ROOT`，后者下需要本地映射、解压依赖与密钥候选文件，详见探针源码中的相对路径。

```powershell
$env:PBZ_PAKS = '你的游戏目录/ProjectPBZ/Content/Paks'
$env:LEMALIN_REFERENCE_ROOT = '你的参考工作目录'
dotnet run --project tools/NativeUiProbe

$env:LEMALIN_PLAYER_RELEASE = '1'
$env:LEMALIN_REUSE_LIVELY_MESH = '0'
./tools/run_unreal.ps1 ue_build_lively.py
```

生成器执行动态网格导入，建立辫子和兔耳物理、动画图、材质切换与面板，最后覆盖实际显示入口。初次需要导入网格，之后只改逻辑时可将 `LEMALIN_REUSE_LIVELY_MESH` 设为 `1`。

玩家分支使用独立保存槽 `Hcxmmx_LeMalin_Player_v1`，开发面板使用 `Hcxmmx_LeMalin_Settings_v1`。玩家七项设置与默认值见玩家说明。制作期开发图和诊断工具保留在源码里。

## 第五步，烹饪与白名单打包

```powershell
./tools/cook.ps1 -UnrealRoot $env:UNREAL_ROOT -Version 0.2.0
python tools/package_test.py --version 0.2.0
```

`metadata/cook-allowlist.json` 决定打进容器的资源。生成脚本会增删相关条目，它既保留了本次最终清单，也承担后续生成阶段的工作清单用途。

打包会排除前作目录、游戏材质/UI 参考资源、编辑器桩和预览资产，生成独立 `.pak/.utoc/.ucas`。`global.utoc/global.ucas` 是本地打包辅助产物，玩家安装包仅收录模组自身三件套。

第一次接入新模型时，检查实际显示入口、动画与材质绑定及一次基础动作。参数小调已有清晰作用链时，直接构建部署并实机观察即可。

## 验收与复现范围

本次动态、材质、表情、眼神、玩家面板和语音均经过实际游戏多轮反馈。公开整理时增加了路径推导和工具包装，未重新从空游戏参考工程跑完所有历史阶段。源码能定位本次实现，完整复现仍依赖前面列出的外部输入。

推荐先按自己现有的游戏参考工程完成一条最小显示与动作链，再依次加入物理、材质变体、表情和面板。换模型时优先检查源数据与映射，LeMalin 的辅助骨编号、UV 岛和物理形状需要重新配置。
